Multicam + audio switcher in Remotion

Two shots on one shared timeline. Cut between them and choose the audio, live, while it plays.

0.00s

Keys: 1/2 shot A/B · Q/W/E audio A/B/none · Space play/pause. Use the offset to line up the shots until the audio matches the picture.

How it works

Remotion renders video as React. Here a single composition (src/Multicam.tsx) mounts both clips at all times, each inside a <Sequence>, so they play frame-locked together:

  • Shot switching changes only the opacity of each layer (the “cut”). Nothing reloads, so cuts are instant.
  • Audio selection changes only the volume prop (1 or 0) of each clip’s own audio track. You can see shot B while hearing A.
  • Lining up: offsetB (frames) moves B’s <Sequence from> relative to A. Duration is recomputed from the offset.
  • Live preview: @remotion/player embeds the composition in a normal web page and re-renders it as props change. This page is a static Vite build hosted on GitHub Pages.
  • Export: the same composition renders to mp4 with npm run render (props such as --props='{"shot":"B","audio":"A"}').
<Sequence from={shift + offsetB} durationInFrames={DUR_B}>
  <Video src={staticFile('shot-b.mp4')}
         volume={audio === 'B' ? 1 : 0}
         style={{opacity: shot === 'B' ? 1 : 0}} />
</Sequence>

Sources: shot A 1024×576 @30fps, 19.4s · shot B 736×480 @60fps, 37.7s (fit with object-fit: contain). Both include AAC audio.
