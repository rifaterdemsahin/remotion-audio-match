Multicam + audio switcher in Remotion

Two shots lined up on one timeline by their shared audio. Cut between them and choose the audio.

Proof it works in Remotion Studio

How the shots are lined up (two tactics, cross-checked)

Both clips recorded the same speech, so the audio is the sync reference. I used two independent tactics and only trusted the result because they agree.

TacticWhat it doesResult
1. TranscriptionWhisper (large-v3-turbo, run locally) transcribes each clip with word timestamps. Every word spoken in both clips gives a vote tA − tB; the tallest cluster wins.−9.78 s (±0.25)
39 of 89 matches agree
2. WaveformCross-correlates the raw audio (coarse pass on loudness, then fine pass on samples). Then a check: correlate 2 s windows across the whole overlap and confirm every window gives the same lag.−9.782 s
18/18 windows, ±1 ms, no drift

Why both? Transcription understands what was said but is only accurate to ~0.25 s and fails on noisy speech (the small model produced gibberish). The waveform is accurate to about a millisecond but cannot tell a real match from a lucky one on its own. Transcription tells you roughly where; the waveform tells you exactly; agreement proves it. The windowed check also guards against drift, which matters here because the clips are 30 and 60 fps phone/screen recordings.

Reproduce it:

whisper shot-a.wav shot-b.wav --model large-v3-turbo --word_timestamps True --output_format json
npm run sync:transcript   # tactic 1 → -9.78 s
npm run sync:waveform     # tactic 2 → -9.782 s
npm run sync:verify       # window-by-window check → no drift
# then put the number in src/lib/sync.ts; Remotion does the rest

Other things I did: started with the small Whisper model, saw it fail, and switched to large-v3-turbo; used the loudness-envelope pass to narrow the search before the sample-level pass; and rounded the final offset to whole frames (−293 @30fps), since Remotion places clips on frames.

Picture-in-picture

The PiP composition (src/compositions/PiP.tsx) shows both videos at once: the long clip B is the full-frame base, and the shorter clip A sits inside it. A “activates” at its lined-up start (9.78 s): it springs in with a pulsing red SHOT A badge, plays in sync, and shrinks away when it ends at 29.2 s. Props let you change corner, insetWidth, which audio you hear, or swap which clip is the big picture (insetSwapped). Export it with npm run render:pip.

How it works

  
Everything happens inside the Remotion composition (src/compositions/Multicam.tsx); this page only embeds it with @remotion/player.

  
    
    
  • Line-up: the measured offset (B started 9.78 s before A, see above) lives in src/lib/sync.ts. The composition places each clip in a <Sequence from=…> accordingly, so picture and sound of both shots are aligned.
    • 
    
  • Cut list: a cuts prop ({at, shot, audio}) says which shot is visible and which audio is heard from each moment. Default: B until A begins, cut to A, back to B when A ends, with B’s audio throughout. Edit it live in Remotion Studio’s props panel.
    • 
    
  • Both clips always play, so cuts are instant: shot = opacity, audio = volume.
    • 
    
  • Buttons above temporarily override the cut list so you can audition any shot/audio combination.
    • 
    
  • Export: npm run render writes the edit to out/multicam.mp4; npm run studio opens Remotion Studio.
    • 
  

  
const offsetB = Math.round(B_OFFSET_SECONDS * FPS);   // -293 frames
const START_A = Math.max(0, -offsetB);                // A begins 293f in
<Sequence from={START_A} durationInFrames={DUR_A}>…</Sequence>
